## Executive summary

The platform core (owner gate, proxy-secret/CSRF layering, app isolation
namespaces, dataset registry, pack verification, upgrade guard) is materially
harder than at the previous baseline and most prior High findings are fixed.
The regressions are at the edges:

1. **Buddy-disabled installs crash on a single authenticated request.** The
   `/api/buddy/v1/*` routes are mounted even when the receiver is not configured,
   and the `BuddyState` extractor `expect`s it to exist. `panic = "abort"` turns
   that into an API-process kill; any `naslos_users` account can trigger it
   through Authelia's one_factor policy. The **live node is in this state**
   (`buddy.enabled: false`, no `BUDDY_*` env) — it was not probed because the
   probe would crash it (`AUD-2611-T6-1`).
2. **The release gate was red at the tag.** `scripts/audit.sh` failed 2 checks:
   `cargo audit` and `cargo deny` both flagged four `hickory-proto 0.24.4`
   advisories. **Fixed on this branch** by the 0.26.3 upgrade; the gate is green
   (`AUD-2611-A-1`, `AUD-2611-T3-1`).
3. **Disabled users can still log in.** The API disables a person by setting
   `shadowExpire=1`, but Authelia's `users_filter` never tests `shadowExpire`, so
   a disabled account keeps its LDAP password and group membership and still
   obtains an Authelia session (`AUD-2611-T1-1`, prior `SEC-2026-A6`).
4. **Insecure catalog defaults.** 22 of 33 apps ship `exposure.auth: false` and
   every app ships `internet: true`; Prowlarr additionally defaults
   `disableAuth: true`, so accepting the defaults publishes an admin interface
   with no login at all. The UI does show a red confirmation gate, which limits
   this to a consent problem rather than a silent bypass (`AUD-2611-N-1`,
   `AUD-2611-N-2`).
5. **Catalog-wide container hardening is absent.** No catalog app sets
   `runAsNonRoot`, `allowPrivilegeEscalation: false`, capability drops,
   `readOnlyRootFilesystem`, or `automountServiceAccountToken: false`
   (`AUD-2611-N-3`).
6. **Reachable DNS parser CVEs.** `hickory-resolver 0.24.4` was reachable from
   the DDNS IP-discovery path; **fixed on this branch** by the 0.26.3 upgrade
   (`AUD-2611-T3-1`).

Severity counts (register below): see *Severity counts*.

## Inventory

### Entry points

**Public (no proxy auth):** `GET /api/health`, `GET /api/ready`,
`/api/buddy/v1/*` (Ed25519 peer signature, not the proxy).

**Authenticated, any user:** `GET /api/auth/me`, `/api/dashboard`,
`/api/metrics`.

**Owner/admin only** (`require_admin`, group `naslos_admins`): everything else
under `/api/` — catalog/sources, apps lifecycle, exposure, quotas, pods/logs and
exec WS, domains/certs/SSO, providers/DDNS, system upgrade/reboot/operations,
disks/ZFS/datasets, shares, notifications, buddy owner API, users/groups,
dataset registry. Unknown `/api/*` paths stay behind auth (`not_found` after the
owner layers) so their existence is not leaked.

Source: `rust/api/src/server/mod.rs:39-247`.

**Agent** (`rust/agent/src/server/mod.rs:88-167`): `/health` public; every
`/api/v1/*` route requires `Authorization: Bearer <token>` (constant-time
compare, fails closed when the token is empty —
`rust/agent/src/server/auth.rs:12-38`).

### Trust boundaries

```
Internet ──TLS──> Traefik (naslos) ──forwardAuth──> Authelia ──LDAPS──> OpenLDAP
                        │  strip-client-identity + proxy-identity (shared secret)
                        ├─ /api  ──> naslos-api (owner gate + admin group)
                        └─ app hosts ──> app pods (per-namespace NetworkPolicy)
naslos-api ──bearer+TLS──> naslos-agent (hostNetwork, privileged ns)
naslos-api ──SA──> kube API (namespaced roles + a few cluster roles)
```

- `TRAEFIK_CIDR` defaults to the whole pod CIDR `10.244.0.0/16`
  (`charts/naslos/templates/_helpers.tpl:21-26`), so the shared secret — not the
  CIDR — is the identity proof; the NetworkPolicy is the real network boundary.
- `naslos-api-ingress` admits only Traefik, the UI, and the whole
  `naslos-privileged` namespace (`charts/naslos/templates/networkpolicy.yaml`).
  App namespaces cannot reach the API.
- The shared secret is stored as a literal in the `proxy-identity` Traefik
  Middleware CRD (prior A4), not in a Secret; `/traefik` is denied to everyone
  (`authelia-config.yaml`).
