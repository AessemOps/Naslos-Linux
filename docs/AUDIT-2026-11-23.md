# Full code review — v0.7.1 (master `daf1bfd`), 2026-11-23

Read-only review of the complete v0.7.1 release state (master tip, one commit
past the `v0.7.1` tag). Seven parallel deep dives covered: API core
(auth/RBAC/audit/state), API apps+storage (Helm/ZFS/schedules/replication),
Buddy + MCP, API integrations (alerts/DNS/domains/config import-export), the
privileged agent + vmd, the Svelte UI + e2e suite, and the chart/scripts/release
pipeline. ~87 distinct findings; every 🔴 was re-verified in-source after the
reviews. The ordered fix plan is
[`.kilo/plans/2026-11-23-0.7.1-remediation.md`](../.kilo/plans/2026-11-23-0.7.1-remediation.md).

**Overall verdict:** the 0.7.1 remediation integration is solid — ZFS argv
discipline, Buddy signature/replay verification, MCP scope plumbing, config
export canaries, chart default-deny, and the agent/vmd token+TLS posture are all
genuinely good. The serious defects cluster in three places: **the web upgrader
is deterministically broken and its admission policy is bypassable**, **the Buddy
quota can be bypassed by an enrolled peer**, and **several stores/UI flows fail
open on errors in ways that destroy or corrupt user data**.

Findings are tagged per subsystem: A (API core), S (apps/storage), B
(Buddy/MCP), I (integrations), P (agent/vmd), U (UI), C (chart/pipeline).

## 🔴 Blocking (5)

### C-1a — Every web-upgrade Job is denied by the chart's own admission policy
`charts/naslos/templates/system-upgrade.yaml:147` vs `rust/api/src/system.rs:861-862`.
The VAP arg allowlist is `^--(op|operation-id|from|version|pack-url|sha256|namespace|release)(=|$)`
but `job_spec` always emits `--pack-sig-url` and `--pack-pubkey`. The API
returns `202`, the upgrade can never start. `scripts/audit.sh` asserts the same
stale regex, so CI cannot catch it. (Found independently by two reviewers;
verified in-source.)

### C-1b — The upgrader admission policy is bypassable; the cluster-admin SA is not contained
`charts/naslos/templates/system-upgrade.yaml:113-198`. The policy never checks
`lifecycle`, `*Probe.exec`, `envFrom`, container-level `runAsUser`/`privileged`/
`capabilities.add`, or pins the `talosconfig` Secret / `state` PVC names. A Job
with the official image and `command: ["naslos-upgrade"]` can add
`livenessProbe.exec.command: ["/bin/sh", …]` and run arbitrary code as the
`naslos-upgrader` cluster-admin SA; the probe can read the Talos config Secret
and the Buddy KEK. The "API image is distroless (no shell)" comment in
`api-deployment.yaml:106` is false (Alpine base). Defeats FR-UPD-07.

### C-1c — The upgrader pod has no network path to download the pack
`charts/naslos/templates/networkpolicy.yaml:417-526`. No egress policy selects
the `naslos-system-op` Job pod (namespace default-deny is live under Cilium),
and the image/git/DDNS policies select only the API pod. Even with C-1a fixed,
`download_and_extract` fails. Preferred fix: hand the Job the API's
already-verified cached pack path on the shared state PVC instead of
re-downloading.

### B-1 — Buddy quota and free-space reserve are bypassable by an enrolled peer
`rust/api/src/buddy/store.rs:168-196, 217-220, 818-820, 896-918`;
`server/buddy.rs:745-752`. Zero/1-byte chunks make `delta == 0` and skip both
quota and the 1 GiB `free_space()` check while still creating files/inodes;
manifests are never quota-charged and their `sealedBytes` claim is never
verified against the actual chunks; chain ids may start with `.`, and
`dir_size` skips dot-named directories — so usage can be zeroed while data
persists. An authenticated peer can fill the receive dataset despite a 1 MiB
quota, contradicting `docs/buddy-backup.md` §quotas. Verified in-source
(`reserve_usage` returns early on `delta == 0`).

### U-1 — VM edit corrupts or cannot save the record
`ui/src/lib/components/VmWizard.svelte:20-24, 260-278`. Edit clones the
**server** shape (`structuredClone(vm)`) into a form that assumes the UI shape:
VMs without `cloudInit` crash the wizard (`form.cloudInit.enabled`); VMs **with**
cloud-init lose the section (no `enabled` flag server-side) so any edit omits
`cloudInit` from the PUT and **silently erases hostname/user/SSH keys**; VMs
without `net.forwards` cannot be saved (`forwards.map` on `undefined`). Verified
in-source.

## 🟡 Important (35, merged across reviewers)

### Web upgrader (pairs with the 🔴 cluster)
- **I-5** `upgrade/ops.rs:130` — an image-digest mismatch after the Helm
  upgrade fails the operation **without rolling back** (FR-UPD-06); also
  verifies pod-template images, not running pods.
- **I-7** `system.rs:367-370, 608-644` — pack downloads follow up to 10
  redirects, validate only the first hop against `pack_url_allowed`, and
  `download_bytes` allocates the whole body before the 512 MiB cap check.

### Buddy / MCP
- **B-2** `store.rs:217-248, 648-651` — quota accounting racy
  (`dir_size` outside the usage mutex; `unwrap_or(0)` on I/O error) and stale
  after prune (cache never invalidated on the prune path).
- **B-3** `buddy/peers.rs:209-214`, `mcp/store.rs:342-351`, schedules/chartsrepo
  stores — revocation mutates memory before save; a failed save (full/read-only
  state volume) reports success and the revoked peer/MCP token/schedule
  resurrects after restart. Security control fails open.
- **B-4** `server/buddy_restore.rs:327-335` — the rollback snapshot is
  destroyed even when the rollback **failed**; progress marker removed
  unconditionally; a fresh-dataset failure leaves a half-applied receive with
  no recovery point (contradicts `docs/buddy-backup.md:457`).
- **B-5** `buddy/client.rs:278-324, 1105-1145` — restore trusts
  receiver-supplied (unsigned) chain summaries; signed manifests'
  `from/to_guid`/`kind` are never cross-checked before plaintext is written;
  the monotonicity anchor is a per-client file and skipped when `0`.
- **B-6** `store.rs:355-377` — a new chain with a lower sequence is accepted;
  equal-sequence re-PUTs are assumed byte-identical without comparison.
- **B-7** `buddy_restore.rs:197-210` — concurrent restores interleave per-chain
  receives; one progress file keyed by source only; a second restore deletes
  the first's crash marker.
- **B-8** `bin/buddyctl.rs:387-437` — `push --dir` follows symlinks into the
  tar; a planted `ln -s` to the buddy identity can archive the private key/KEK
  off-node.
- **B-9** `mcp/tools/mod.rs:115-117` — `buddy_send` and
  `buddy_schedule_create` are Write-scoped but take arbitrary receiver URLs →
  a Write token gets the API to egress sealed backup streams to any host,
  persistently on a schedule. Contradicts the documented `full`-for-egress
  rule; fix by reclassifying to `full` (test: no Write tool has an http(s) URL
  argument).
- **B-10** `buddy/client.rs:607-614` — any HTTP 3xx is treated as success, so
  a redirecting receiver yields a false "backed up" with no restorable backup.
- **B-11** `buddy/auth.rs:140-209` — nonce persistence is not crash-atomic
  (append + compaction race; no fsync); after a restart a captured request can
  be replayed within the window.

### Privileged agent / vmd
- **P-1** `agent/server/mod.rs:301`, `vmd/server/mod.rs:138` — agent (:9090) and
  vmd (:9091) bind `0.0.0.0` on hostNetwork. Token auth is real (fail-closed,
  constant-time, TLS default — the prior unauthenticated posture is **fixed**),
  but the `naslos-allow-host` Cilium policy grants `toEntities: [host]` with no
  port list to every pod in both platform namespaces. Defense-in-depth gap.
- **P-2 / C-9** `networkpolicy.yaml:750-830` — the optional `hostFirewall`
  template's comment is false: `fromEntities: [cluster]` on 9090 (not
  API-pod-scoped), 9091 missing entirely (enabling it would break the VNC
  tunnel), public 80/443 not allowed.
- **P-3** `agent/zfs/operations.rs:293-305` — the agent will `wipefs --all` any
  whole disk including the Talos system disk; the `system_disk` guard exists
  only API-side. The agent is supposed to be the last line of defense.
- **P-4** `vmd/supervisor.rs:93-127, 377-386` — `apply()` spawns unserialized
  reconciles; two pushes can double-start a VM, orphan a QEMU (no
  `kill_on_drop`), and wedge every later start on the image lock/display.
- **P-5** `vmd/supervisor.rs:139-146` — a crashed VM is never restarted and
  `start()`/`stop_one` treat a reaped entry as alive.
- **P-6** `agent/server/handlers.rs:1123-1126`, `agent.rs:1274-1313` —
  `zfs receive` converts mount errors to warnings and the API ignores the body;
  recursive replication leaves children unmounted (writes land in shadow
  directories).
- **P-7** `vmd/images.rs:70, 102-126, 200` — the 32 GiB image cap is not a cap
  (per-request check; over-cap leaves the larger file), uploads write in place
  (no staging/ownership), `File::create` at offset 0 silently truncates an
  existing library image, and delete/overwrite works while a VM holds the image.
- **P-8** vmd follows symlinks under `/var/mnt` (disk, vars, log, seed, image
  files) where the agent deliberately does not; a share-account-writable
  directory can redirect a QEMU open/truncate to a host block device.

### API core / state
- **A-1** `audit.rs:775-790, 1686, 1799` — degraded audit mode refuses the
  audit **reads** the operator needs to recover, and a transient
  `ensure_capacity` refusal marks degradation permanently sticky (no recovery
  path short of restart).
- **A-2** `state.rs:161-163, 420-452`, `certs.rs:298`, `virt.rs:56-86`,
  `ddns.rs:121, 473`, `mcp/store.rs:199-241` — persisted stores that fail to
  load are silently **overwritten** by the next write (domains, sources, vms,
  ddns, MCP tokens); only shares/smbusers/schedules fail closed. A corrupt
  `mcp.json` permanently deletes every token hash on the next save.
- **A-3** `audit.rs:940-990` vs `spec.md` FR-AUD-08 — several async handlers
  (buddy receiver, vnc bridge, notifications, ddns) still use the synchronous
  fsync-ing audit API on Tokio workers.
- **A-4** `server/domains.rs:227-229` — `PUT /api/domains/{name}` mutates the
  **body's** `baseDomain`, creating a different domain than the URL and audit
  target name.
- **A-5 / S-4** `chartsrepo.rs:530-587, 755-761` — HTTPS source tokens are
  embedded in the clone URL (visible in argv and persisted in the cache's
  `.git/config`, world-readable dirs), and the fetch path reuses the old token
  from `remote.origin.url`, so **rotation never takes effect** until the cache
  is deleted.

### Apps / storage
- **S-1** `apps.rs:1398-1404, 1657-1669` — client values are not constrained to
  the catalog schema (`additionalProperties` not enforced): `image`,
  `privileged`, `hostPath`, `serviceAccount` can be injected on install and
  update. Admin-only, but it defeats the stated SEC-2026-D7 gate and the
  dataset-picker rule.
- **S-2** `apps.rs:1393-1553`, `helm.rs:38-50` — install persists the **entire
  chart defaults** map; upgrade re-sends it with `--reset-values`, so a chart
  bump's changed defaults (including `image.tag`) are never applied.
- **S-3 / I-9** `apps.rs:3445-3463`, `config_export.rs:286-295` — values
  redaction falls back to "nothing" when a catalog entry exists with no
  schema pointers; the persisted `redacted_keys` list is only used when the
  catalog is entirely absent (API reads) and never in config export.
- **S-5** `server/zfs.rs:1495-1507`, `replication.rs:119` — the destroy guard
  counts the last 20 **finished** replication jobs; after one successful
  replication neither source nor destination can be destroyed (misleading
  "wait for it to finish" message) until 20 more jobs or an API restart.
- **S-6** `server/storage_schedules.rs:475-492` — the 1-hour
  transient-failure window never accumulates (`last_run` reset every retry);
  a down agent is retried every minute forever, contradicting the documented
  cadence backoff.
- **S-7** `datasets.rs:47-76`, `server/zfs.rs:1448-1470` — the dataset registry
  loads unvalidated records and fails open in the destroy guard (a dropped
  `attachedTo` un-blocks destroying an app-mounted dataset).
- **S-8** `apps.rs:1416-1420, 4128-4136` — no cross-app uniqueness check for
  `subdomain + baseDomain`; two apps can claim the same host with
  unpredictable route/CNAME ownership.

### Integrations
- **I-2** `config_export.rs:62-75`, `config_import.rs:55-68, 604, 626` — export
  silently drops the SMB `shadowCopies` and `audit` share options (spec DM-4
  includes both); a round-trip disables them.
- **I-3** `server/domains.rs:395, 463-493`, `certs.rs:118-126` — with
  `fields` omitted, `credentialsSecret` is accepted unvalidated (any Secret
  name; the documented DNS-1123/`naslos-` guard is bypassable) and a provider
  change skips effective solver/fields validation. The **specific WP-11
  omitted-`solver` bug is verified fixed** (`solver_submitted` at :374, empty
  clearing rules at :383-390); this is the remaining effective-validation hole.
- **I-4** `notifications.rs:160-239`, `server/notifications.rs:104-111` — the
  ntfy test endpoint reports "sent" when the severity floor dropped the
  message with default settings.
- **I-6** `server/virt.rs:66-78` — VM delete/restore treats a VM **absent from
  the vmd live report** as stopped (fail-open during vmd restart/reconcile),
  contradicting the function's own contract comment.

### UI (data-destroying error paths)
- **U-2** `DomainForm.svelte:38-61, 126` — a failed `/api/ddns` GET during
  domain edit sends `appRecordsDdnsEntry: null` and silently detaches every

- **U-3** `DomainForm.svelte:104-114, 223`, `DdnsForm.svelte:62-72`,

- **U-7** `ui/vmd-drill.mjs:176-206` — the operator drill omits the new

- **U-8** `vms/+page.svelte:336-338`, `VmWizard.svelte:50-51` — the wizard is

### Chart / pipeline
- **C-4** `app-admission.yaml:1-43`, `rbac-helm.yaml:41-72` — the app-isolation
  VAP denies only `networking.k8s.io` writes; `traefik.io` IngressRoutes and
  `cert-manager.io` (the host-hijack paths) are not denied, the Helm Role can

- **C-6** `workflows/release.yml:168-177`, `check-release-version.sh:63-83` —

- **C-7** `scripts/deploy-vm.sh:393-408` — tag overrides are silently ignored

- **C-10** openldap StatefulSet/bootstrap/API init containers run as root

## Verified fixed / prior items closed in 0.7.1

- **The WP-11 solver passthrough defect is fixed**: `solver_submitted`
  distinguishes omitted (preserve) from explicit empty (clear), validation
  runs against the effective stored-plus-submitted value, and `domain_view`
  never echoes the solver (`server/domains.rs:353-399, 493`). The UI contract
  matches on the normal path.
- Agent/vmd listeners now require bearer tokens (fail-closed, constant-time)
  with mandatory TLS and CA pinning — the previously identified
  unauthenticated-privileged-listener posture is closed at the auth layer.
- ZFS argv discipline (no shell anywhere), dataset/snapshot/schedule
  validators applied on every handler, GUID-bound destroy, encryption key
  custody (0600 unlinked keyfile, never in argv/JSON/logs).
- Buddy core auth: canonical string binds method+path+query+body digest, nonce
  cap refuses rather than evicts, enrollment single-use under a mutex,
  self-send loopback rewrite conservative, restore verifies
  signatures before any `zfs receive`, tar extraction rejects `..`/symlinks.
- Config export canaries + fail-closed import envelopes; SSRF guards on
  webhook/ntfy/DDNS (literal + resolved + per-request pinning, redirects
  disabled); chart default-deny rewrite structurally thorough; OpenLDAP
  credentials chart-generated with `lookup`/keep; samba/nfs/backup CronJob
  hardened; release pack digest pinning fail-closed.

## Done well (highlights)

- Schema/projection discipline across DDNS/domains/notifications/audit views
  (write-only credentials, redacted Debug impls, `proc::scrub`).
- The route inventory: all 117 registered routes classified, middleware order
  verifiable, `internal_router` never mounted, regression tests sweep auth.
- Atomic writes with explicit modes, `.corrupt-<ts>` backup + fail-closed in
  the stores that have the pattern (schedules, shares, smbusers).
- Chart commentary is unusually explicit about intent and residuals; the
  app-admission VAP and `test-app-isolation.sh` are the right
  defense-in-depth ideas (they need wiring + widening, see C-4).
- UI: no XSS sinks, no secrets in storage, shared `use:modal` focus management,
  race guards on recently-touched components.

## Coverage / limits

Fully reviewed: all of `rust/agent/src`, `rust/vmd/src`, the listed API module
sets (core, apps/storage, buddy, mcp, integrations), all 38 chart templates,
scripts, workflows, the 0.7.1 UI diff and its contract counterparts, and the
image dirs. Skimmed: unrelated owner handlers, non-changed UI areas for
sink/secret patterns, bootstrap Cilium config. Not run: cargo tests, helm
lint, Playwright, or live drills (read-only review of a detached worktree);
CI is green per the release commit. Needs live drills: the upgrader Job on a
VAP-enabled node (C-1a is deterministic), quota/inode exhaustion against a
test peer (B-1), export/import of a shadow-copies share (I-2), a chart-bump
app upgrade (S-2), vmd concurrent create+start (P-4), and the values-vm
digest-vs-release check on the next release (C-6).
