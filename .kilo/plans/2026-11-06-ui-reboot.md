# UI: reboot the Talos node

## Goal

Add a confirmed "Reboot node" action to `/system` so an operator does not need
console/talosctl access for a plain reboot (independent of the upgrade flow).

## Design

- API: `POST /api/system/reboot?confirm=reboot` runs the bundled `talosctl
  reboot` through the API's existing Talos adapter (the API already mounts the
  admin talosconfig). It works on both installer and `make install-vm` nodes.
- The API returns `202 {"status":"rebooting"}` after the Talos API accepts the
  request. The connection may drop as the node goes down, so the UI treats a
  network/502 failure as expected and polls `/api/system/version`.
- UI: a Node card on the System page with a modal that requires typing
  `reboot`; after submission it shows "node rebooting, reconnecting..." and
  polls until the API answers, with a 10-minute cap.

## Safety

- Confirmation token (`confirm=reboot`) plus typed UI confirmation.
- No changes to the upgrader Job, release facts or RBAC; the API already holds
  the Talos credentials.
- Shares/apps go offline during the reboot; the UI states this explicitly.

## Verification

- `cargo test -p naslos-api --lib server::system` (or the workspace tests).
- `npm run check && npm run build` for the UI.
- Live: restart the API hotfix, then exercise the endpoint against the node.
