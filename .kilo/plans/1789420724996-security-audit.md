# Security Audit Plan — Naslos Full Codebase (Static + Config Review)

## Goal
Produce `docs/SECURITY-AUDIT.md`: a severity-rated, evidence-backed security audit of the full Naslos codebase (no live exploitation, no source fixes in this pass). Covers confidentiality, integrity, availability risks an implementation agent can remediate in follow-ups.

## Scope (user-confirmed: Full codebase)
- `api/` (Go: server routes, auth middleware, agent client, talos, helm, identity/LDAP, shares, notifications, metrics, buddy send/jobs/schedules)
- `agent/` (Go DaemonSet: privileged zpool/zfs exec, HTTP server, input validation)
- `api/internal/buddy/` (auth signing/replay, envelope AES-GCM, store, peers, HTTP surface, sender client)
- `ui/` (SvelteKit routes, fetch usage, nginx.conf routing/access control)
- `charts/naslos/` (deployments, RBAC Roles/ClusterRoles, hostPath/hostNetwork/privileged, values.yaml + values-vm.yaml secrets, ingress/TLS, Traefik middlewares)
- `samba/`, `nfs/`, `openldap/`, `terminal/`, `zsh-terminal/`, `bootstrap/` (images, entrypoints, config rendering, default creds)
- Dependencies: `api/go.mod` (govulncheck), `ui/package.json` (npm audit)

## Out of scope / constraints
- No source-code fixes in this audit pass; report only.
- No live destructive testing, no writes to VM/cluster, no credential rotation.
- No dynamic fuzzing/exploitation; read-only static review + local vuln scanners only.
- Plan-mode author cannot write `docs/`; an implementation-capable agent executes this plan.

## Report shape (`docs/SECURITY-AUDIT.md`)
- Header: date (2026-09-14), commit SHA + branch, scope, methodology, what was NOT tested.
- Executive summary: counts by severity + top 3 risks in plain language.
- Findings: ID (e.g. NAS-001), title, severity (Critical/High/Medium/Low + why), affected files:lines, description, exploit precondition (e.g. "reachable via ClusterIP without auth"), recommendation. Order Critical→Low.
- Appendix A: route→auth matrix. Appendix B: privileged/RBAC table. Appendix C: secrets/defaults table. Appendix D: dependency scan output. Appendix E: open questions / needs-live-verification list.
- Remediation checklist ordered by risk (checkbox list, no code changes in this doc).

## Severity rubric
- Critical: unauthenticated RCE / data destruction / full auth bypass (e.g. agent privileged ops, terminal exec).
- High: authenticated RCE, privilege escalation, peer-auth bypass, secrets exposure, cluster-root paths.
- Medium: missing defense-in-depth (origin checks, log-stream auth, over-broad RBAC, weak defaults, TLS gaps).
- Low/Info: hardening opportunities, verbose errors, missing headers/limits.

## Failure modes / edge cases to note in report
- API reachable directly (ClusterIP/NodePort) bypasses Traefik forwardAuth — state this assumption explicitly.
- Agent HTTP reachable in-cluster = privileged exec; note NetworkPolicy absence if confirmed.
- Host-namespace mount gotcha (AI_Handoff) does not weaken audit conclusions; note where quota/isolation assumptions break.
- Registry tag reuse (`0.1.0` + IfNotPresent) risks stale-image verification — note as supply-chain observation, not a code finding.
