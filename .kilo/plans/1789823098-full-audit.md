## Ground rules (non-negotiable)

- **No secret values in any artefact.** Reports cite key names, locations and
  file:line only. A live secret that is found valid is documented and flagged for
  rotation, never exercised beyond its intended path.
- **Non-destructive by default.** No `zpool create/destroy`, no `zfs destroy`, no
  `wipefs`, no share/user deletion of real data, no credential rotation, no
  disabling Authelia/2FA, no deploying a bypass. Test artefacts use throwaway
  names prefixed `audit-` and are deleted in a cleanup step.
- **Active tests only from the approved list**, with a maintenance window for
  anything that restarts a workload; rollback is `helm -n naslos rollback`.
- **Stop conditions:** unexpected destructive effect, data-loss risk, cluster
  degradation, or a finding that itself implies lateral movement.
- Capture a pre-audit snapshot first: `git rev-parse`, `helm -n naslos get values`,
  `kubectl -n naslos get all -o yaml` (read-only), Talos config backup.

## Tracks

### T1 — Secrets and key management (SL-*) — skill: security-best-practices
Contents: git history and working tree; Helm values vs generated Secrets; the
`naslos-proxy`/`naslos-agent`/`naslos-tls`/Authelia `jwt_secret`/LDAP/OpenLDAP
admin/Grafana/notify creds; `bootstrap/vm/talosconfig*`; `support-naslos-vm.zip.age`;
`ui/.env.playwright.local`; `ui/tests/.auth/admin.json`; container env and image
layers; Terraform/ISO configs; docs and commit messages.
Checks: full-history secret scan; entropy + pattern scan; whether any secret is
committed, in an image layer, in logs/metrics, or echoed by an API; how each is
generated (randAlphaNum on every render is a known hazard — the Authelia
`jwt_secret` is regenerated per render; decide if that rotates state on upgrade);
rotation/backup story; file modes; `lookup`-persistence correctness.

### T2 — Authentication, authorization, session (SEC-*) — code-review Security guide
Contents: `api/internal/auth/*`, `api/internal/server/server.go` route composition,
Authelia config, Traefik middlewares, terminal/buddy per-handler checks.
Checks: route-table completeness (no bare owner route — property test); secret
comparison constant-time; CIDR trust; `Remote-*` spoofing; admin gating (CR-03);
WS upgrade gating and origin (NAS-009); session cookie flags/CSRF on state-changing
POSTs; rate limiting/regulation; the peer API bypass scope; the Traefik dashboard
gate; logout/session fixation.

### T3 — Input handling and injection (SEC-*) — Security guide + Universal Quality
Contents: pool/dataset/snapshot/share/user/group/schedule/job inputs; the agent's
`chroot` exec layer; LDAP filters/DNs; smb.conf/Ganesha/NSS renderers; Helm values
passed through; JSON/YAML decoders.
Checks: flag injection via leading `-`, path traversal, newline/`]`/`"` injection,
LDAP filter metachars, DN escaping, oversized inputs, TOCTOU on paths, missing
`ValidatePoolName`/`normalizeDiskPath` on any sink (NAS-003 class), decoder
strictness (`DisallowUnknownFields`), error messages that leak.

### T4 — Crypto and backup integrity (SEC-*) — Security guide
Contents: `api/internal/buddy/*` (envelope, keys, quota, nonces, store, http,
client), the receiver container, restore path.
Checks: KEK handling, key rotation/revoke, sealed-chunk authentication (AAD),
nonce uniqueness + persistence, replay/rollback, quota accounting, chunk-size
bounds, path handling of chunk keys, restore verification, and whether a
compromised peer can overwrite another's chain.

### T5 — Agent privilege and node surface (SEC-*) — devops + Security guide
Contents: `agent/` (server, zfs/dataset/backup/shares), the DaemonSet.
Checks: token enforcement (done — verify no regression), endpoint validation,
`chroot /host` command construction, hostPath mounts (`/`, `/dev`, `/run`,
`/var`), `hostNetwork`/`hostPID`, `privileged`, RBAC, what a compromised agent
grants, and whether the agent is reachable by non-API pods (NetworkPolicy).

### T6 — Kubernetes and Helm hardening (K8S-*) — devops-troubleshooter
Contents: all 17 chart templates + `templates/*.yaml`, namespace PSA label, RBAC,
services, probes, resources, PDBs, secrets, TLS, Traefik/Authelia values.
Checks: PSA/`privileged` namespace-wide (CR-37), over-broad/unused RBAC, missing
probes/PDBs/limits, `hostPath`/`hostPort` justification, image pull policy vs
mutable tags, secret mounting vs env, NetworkPolicy absence (does flannel enforce
it?), namespace hardcoding vs `.Release.Namespace` (CR-38), schema validation
absence, values that silently render nothing.

### T7 — Supply chain, dependencies, images (SUP-*) — docker-expert
Contents: `api/go.mod|sum` (~140 modules), the token-less `agent` module, UI
`package.json`/lockfile, Dockerfiles (`api`, `api/Dockerfile.receiver`, `agent`,
`ui`), the base images, registry at `192.168.1.2:30095`.
Checks: `govulncheck`, `npm audit` (prod + full), outdated/deprecated deps; known
CR-05 (helm.sh/helm < 3.18.5 reachable vulns) and CR-31 (xterm→@xterm); image
digests vs mutable tags; non-root (UI nginx runs root), read-only rootfs, base
image pinning, `.dockerignore` absence (CR-10), SBOM; the registry is HTTP (plain)
— confirm the node pull path.

### T8 — Code quality and architecture (CQ-*) — code-review Go + Universal Quality
Contents: `api/` and `agent/` packages, error handling, concurrency, context,
resource cleanup, dead code (e.g. `identity/samba.go` per CR-24), duplication,
naming, package boundaries, `-race`.
Checks: `go vet`, `staticcheck`, `gosec`; race tests (CR-06 is known failing);
goroutine leaks/timeouts in streaming paths; unbounded reads/writes; error
wrapping and swallowed errors; test quality and coverage per package (CR-43);
spec-vs-code drift (CR-24/25/42/44).

### T9 — Frontend and UI (UI-*) — web-design-guidelines + code-review Svelte
Contents: 24 Svelte files, `nginx.conf`, CSP/security headers from Traefik.
Checks: XSS via rendered API data (`{@html}`/`innerHTML`), client-side trust
decisions, token/secret handling in the browser, terminal xterm handling, error
surfacing (CR-19/22 done — verify), accessibility/UX per the guidelines, CSP
presence, asset integrity, and the `/traefik` link's admin gating.

### T10 — Operations, deployment, observability (OPS-*) — devops-troubleshooter
Contents: `scripts/deploy-vm.sh`, `Makefile`, docs runbooks, monitoring
(Prometheus/Grafana/Alertmanager), notifications, backups/restore, upgrades.
Checks: default credentials in docs/values (`CHANGE_ME`, grafana `naslos-admin`,
registry `secret`), destructive-script paths, upgrade safety (hostPort rollout,
config checksum), recovery without the removed bypass, alert coverage for auth
failures/agent 401s/disk health, log retention, and whether secrets appear in
logs.

### T11 — Active verification (AV-*) — webapp-testing
Bounded, listed below. Each has a precondition, action, expected result, evidence
and cleanup. **No test may destroy data.**

### T12 — Documentation truth-up (DOC-*) — code-review
Spec/docs vs code: route tables, 2FA/access-control, deployment steps, terminal
docs, architecture (CR-24). Verify every MUST in `spec.md` has a live test and
that the mapping table is accurate.

## Severity rubric

Critical — remote unauthenticated RCE / data destruction / private key or
credential exposure to the network. High — auth bypass, privilege escalation,
authenticated destructive abuse, secret disclosure (logs/API/image), backup
integrity failure. Medium — defense-in-depth gaps (missing NetworkPolicy/PSA/
limits), information disclosure, DoS, dependency CVEs with reachable paths.
Low/Info — hygiene, docs drift, unused RBAC, tiered/non-exploitable CVE.
Each finding also gets a rough CVSS 3.1 vector.

## Risks

- **Live active testing on a single-node appliance can cause downtime or data
  loss** — bounded by the guardrails above, one test at a time, with cleanup.
- **No scanners installed / registry may be blocked** — Docker/`go run` fallbacks,
  otherwise coverage gaps are stated in the report.
- **Prior audits are stale** (2026-09-14, pre-fixes) — findings must be re-verified
  rather than copied.
- **Authelia regulation**: repeated auth probes can ban the admin account; auth
  tests use one valid session and avoid wrong-password loops.
