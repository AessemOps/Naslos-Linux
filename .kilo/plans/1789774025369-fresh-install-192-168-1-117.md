## Phase A — pre-install fixes (branch `fix/chart-auth-and-admin` off `master`)

The current sandbox is in plan mode, so the first implementation action is
`git switch -c fix/chart-auth-and-admin master`.

**A1 — CR-02, namespace deletion.** `charts/naslos/templates/namespace.yaml`: add
`annotations: helm.sh/resource-policy: keep`, with a comment saying that OpenLDAP and
the state volume (holding `buddy-identity.json`) are applied outside the chart, so
`helm uninstall` must not cascade. Verify the annotation renders via
`helm template … | grep resource-policy`.

**A2 — CR-11 + the new IP.** `charts/naslos/values-vm.yaml`: remove the duplicate
`talosConfigSecret` and `agent:` keys; set `authelia.domain: 192.168.1.117`; update
the header comment. Keep `auth.disabled: true` and the UI NodePort 30080.

**A3 — CR-01, Authelia rules.** `charts/naslos/templates/authelia-config.yaml`
(`access_control.rules`): the current `domain: <ip> / policy: bypass` with no
`resources` matches the whole host and, because Authelia takes the **first** match,
voids every rule below it. Replace with, in order:
1. `domain: <ip>`, `policy: bypass`, `resources` scoped to Authelia's own endpoints
   and the health probe (`^/api/(verify|authz|firstfactor|secondfactor|reset-password|logout|user/info|state|configuration|health)(/.*)?$`,
   `^/api/health$`);
2. `domain: <ip>`, `policy: bypass`, `resources: ["^/api/buddy/v1/"]` — the peer API
   authenticates with the peers' own Ed25519 keys (a peer cannot complete a login);
3. `domain: "*"`, `policy: two_factor`, the admin `resources` (users, groups, apps,
   volumes, shares);
4. `domain: "*"`, `policy: one_factor`;
with a comment recording the first-match rule so it is not re-broken.

**A4 — CR-03, authorization granularity.** `api/internal/server/server.go`: keep
`requireOwnerAuth` (auth-disabled aware) and add `requireAdmin` (same passthrough);
register the three routes any signed-in user needs — `/api/auth/me`, `/api/dashboard`,
`/api/metrics` — on the outer router behind `requireOwnerAuth`, and mount the owner
mux behind `requireOwnerAuth(requireAdmin(owner))` so **admin is the default** and a
new route cannot be added un-gated by accident. Tests:
`api/internal/auth/middleware_test.go` gains RequireAdmin cases (non-admin 403,
admin 200, missing user 401); `api/internal/server/routes_test.go` gains the split
(non-admin: 200 on the three, 403 on `/api/users`; admin: 200), while the existing
exhaustive 401 table keeps working (it runs with `authDisabled`, which passes
through both wrappers).

**A5 — Playwright base URL.** `ui/playwright.config.ts`:
`baseURL: process.env.PLAYWRIGHT_BASE_URL ?? 'http://192.168.1.96:30080'` so the
suite can be pointed at .117 (CR-33's first half).

**A6 — gates before install**: `api` `go build/vet/test`, `helm lint` with both
value sets and `helm template` to confirm the annotation/rules render, `svelte-check`
(no UI change but cheap), then commit.

## Phase C — real posture (scoped follow-up, not this session)

Everything below is missing today; each item needs building, not just configuring:

1. **Authelia portal routing.** The UI IngressRoute owns `Host(<domain>)` behind
   forwardAuth, and no route exists for Authelia's own paths, so the login flow
   cannot complete. Decide a hostname (e.g. `naslos.local` in DNS or `/etc/hosts`) or
   a `server.path` portal, then route those paths to the Authelia service without
   forwardAuth.
2. **TLS.** `tls.secretName: naslos-tls` is referenced by `ingress.yaml` and
   `terminal.yaml` but **never created**; generate it (self-signed for the chosen
   hostname) in the chart or `generate-secrets.sh`.
3. **Traefik exposure on the VM.** `values-vm.yaml` sets `traefik.service.type:
   ClusterIP`, so the ingress is unreachable from the LAN. Use `NodePort` with fixed
   ports (web `30081`, websecure `30443`) and verify the subchart accepts them (its
   values schema is strict).
4. **Peer bypass route.** Add an IngressRoute for `/api/buddy/v1/*` straight to the
   API with no forwardAuth (peers authenticate with their own keys); otherwise
   forwardAuth intercepts pushes.
5. **First operator account.** The LDAP bootstrap has only groups with an
   `empty-members` placeholder — no users. Create one (`ldapadd` in the OpenLDAP pod
   with the generated admin password), add it to `cn=naslos_admins`, then enrol TOTP
   (required by the two_factor rules before the users/shares/volumes pages work).
6. **Flip and verify.** `auth.disabled=false` + `ingress.enabled=true`; then check:
   login → dashboard; a non-admin user gets 200 on dashboard/metrics/auth-me and 403
   on admin routes; peers still push; the NodePort owner routes answer 401.
   Keep a break-glass note: `auth.disabled=true` over the NodePort is the way back in
   if the proxy misbehaves.

## Risks

- The registry must be reachable from the new VM (mirror is in the machine config);
  a failure here blocks every image pull.
- `install.disk /dev/vda` with `wipe: true` destroys whatever is on the VM's first
  disk — confirm the VM has no data worth keeping.
- The deploy script assumes the node is in Talos maintenance mode; if it is not, the
  `apply-config --insecure` step misbehaves.
- Buddy needs a ZFS pool and a receive dataset that the script does not create.
- The real posture can lock the operator out (TOTP + `naslos_admins`); start from the
  dev posture and keep the NodePort break-glass.
